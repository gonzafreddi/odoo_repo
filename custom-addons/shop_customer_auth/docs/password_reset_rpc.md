# Password reset RPC contract

Suplex web customers are stored in the custom Odoo model `shop.customer.auth`, not in `res.users` or portal users for this login flow. Each auth record points to the commercial customer in `res.partner` through `partner_id` and stores the application password in `password_hash`.

Odoo stores password reset token hashes in `password.reset.token` using SQL table `password_reset_tokens`. The backend generates the raw token and sends the email, but only the token hash is persisted in Odoo.

## Required Odoo user

Create or use an internal Odoo user dedicated to the NestJS integration and add it to the security group `shop_customer_auth.group_shop_password_reset_api` (`Shop Password Reset API`). Do not expose these methods through a public Odoo controller.

## Models

### `shop.customer.auth`

Stores ecommerce credentials. The password lives in `password_hash`.

### `password.reset.token`

SQL table: `password_reset_tokens`.

Fields expected by the backend:

- `user_id`: Many2one to `shop.customer.auth`.
- `partner_id`: Many2one to `res.partner`.
- `email`: normalized email.
- `token_hash`: hash of the reset token. The raw token is never stored.
- `expires_at`: expiration datetime.
- `used_at`: set when consumed or invalidated.
- `ip`: request IP.
- `user_agent`: request user agent.

## Methods

### `shop.customer.auth.check_password_reset_customer(email)`

Internal helper for NestJS before creating a reset token.

When found, returns `exists: true` plus `auth_id`, `partner_id` and `email`. When not found, returns `exists: false`. NestJS must never forward `exists` to the browser.

### `password.reset.token.consume(values)`

Consumes one token record atomically.

Parameters:

`values` object with:

- `auth_id`: ID of `shop.customer.auth`.
- `email`: customer email.
- `password_hash`: new password hash already generated by NestJS using the login hashing scheme.

Behavior:

1. Locks the token row with `FOR UPDATE`.
2. Rejects used or expired tokens.
3. Verifies the token belongs to the provided `shop.customer.auth` and email.
4. Updates `shop.customer.auth.password_hash`.
5. Marks the token as used.
6. Invalidates other active tokens for the same email/auth account.
7. Creates `shop.password.reset.audit`.

Returns `true` on success. Raises `UserError` for invalid payload or invalid token.
